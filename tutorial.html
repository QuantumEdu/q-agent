What is it

The conductor, not the musician

q-agent is a master orchestrator for full software development cycles. It does not build code directly — it guides the user through the right questions, makes architectural decisions using specialized skills, and delegates technical execution to the correct runtime.

Every decision is traceable as a GitHub Issue in the project repository. Every step produces a documented artifact committed to Git.

⚡ Autonomous after Step 3

The agent guides you through Steps 0–3 with one question at a time. After you confirm Step 3, it operates fully autonomously — only stopping at 3 pre-defined critical gates.

The 3 gates after autonomy starts

01
Scope approval
The /propose output (P4) must be explicitly approved before implementation begins.
02
Symmetric tradeoff
An architectural decision with two equally valid options that have non-trivial tradeoffs.
03
Blocking error
An error that requires context only the user can provide. The agent cannot proceed without it.
Everything else → agent decides

Records the rationale in a GitHub Issue and continues. No unnecessary interruptions.

Plans

3 Plans for every scenario

At Step 0, the agent asks which plan to run. The answer drives the entire pipeline configuration.

Plan A

Greenfield

New system from scratch. Full elicitation, deliberation, and specification before a single line of code.

P0→ P2→ P4→ P5→ P6→ P7→ P8→ P1.5
Plan B

Brownfield

Feature or evolution on existing code. Audits the current codebase first, then reconciles before specifying changes.

Pipeline:
P1→ P2→ P3→ P4→ P5→ P6→ P7→ P8→ P1.5
Plan C

Audit

Review, audit and improve existing code. Produces a full compliance report with severity-labeled Issues per gap.

Pipeline:
P1→ P9 (CAB-RP)
P1 note — MAB-PC tags

Step 0 — Plan Identification

The agent presents the 3 plans and waits for selection. Loads references/plans.md to configure the exact pipeline.

Step 1 — Initial Context (1 question at a time)

All plans: project name · problem · constraints. Plan A adds: end user · hardest constraint · out-of-scope. Plans B/C add: repository URL · specific change or criteria.

Step 2 — Research (Skills invoked)

In order: q-deliberate (architectural deliberation, all plans) → optional q-gbrain-assistant (historical knowledge query) → q-grill-me (deep elicitation, Plan A only).

All output synthesized into an internal PROJECT_CONTEXT.md used as context for subsequent steps.

Step 3 — Meta-Orchestration Gate

Agent decides: single-agent or multi-agent? Which executor runtime? Presents decision with rationale. User confirms → autonomous mode begins.

Tier Capability Profile Primary Models Assigned Steps
Tier 1 (Frontier) Deliberation, spec design contracts, and strict compliance audits. Gemini 3.8 Flash / Pro
GPT-6 Astra / GPT-5.6 Sol		 Step 2 (Deliberation), Step 5 (Spec/Design), Step 7 (CAB-RP Audit)
Tier 2 (Fast / Local) Deterministic coding, test execution, syntax fixes, and zero-latency linter hygiene. Qwen 2.5 (3B/7B ROCm)
Gemini Flash-Lite / GPT-5.6 Luna		 Step 6 (Linters / Hygiene), Step 8 (Atomic TDD), Fast-Track Patches

Step 4 — Infrastructure Setup

Delegates via q-delegate-context (FirstMate pattern). Initializes Flight Recorder (.q-agent/flight_recorder.log) for deterministic milestone tracking, loads/creates .q-agent.json, creates GitHub repo, generates CLAUDE.md, initializes CONSTITUTION.md (with stack, principles and ADR table), initial Issues ([SETUP], [ADR-001], [SCOPE]), and verifies subsystems (SkillVault, Engram, Telemetry).

Step 5 — SDD Pipeline

Executes prompts in the order defined by the plan. Standard storage: openspec/changes/{{CHANGE_ID}}/. Fast-Track shortcut available for Nivel 1. The P4 /propose gate is the first allowed interruption in autonomous mode.

Step 6 — Implementation + Hygiene (SwarmForge pattern)

Sub-phase A — Code implementation

Standard git workflow: Issue → branch → commits → PR → merge. Branches: feature/, fix/, audit/.

Sub-phase B — Hygiene (0 unnecessary tokens)

1. Run linters locally. If exit 0 → proceed, 0 tokens spent. 2. If exit ≠ 0 → invoke q-ci-fixer on git diff files only. Hard cap: 2 passes. 3. Never for cosmetic changes.

Sub-phase C — Constitution & ADR Sync (P04b)

Triggered on architectural changes or every 7 tasks: runs P04b_constitution_sync.md to audit drift, updates the ADR status table in CONSTITUTION.md, and enforces that ADRs are immutable (superseded, never modified in-place).

Step 7 — Closure & Delivery

P09 (CAB-RP) → pre-delivery compliance audit (inmutabilidad absoluta, CodeGraph primero, anti-mock check) → Retrospective Issue → q-session-wrap (Engram + SkillVault + SQLite) → final chat report.

Skills

6 skills, one purpose each

q-agent invokes these skills at specific steps. Each has a single, well-defined responsibility.

🧐
q-grill-me
Step 2c · Plan A only
A relentless socratic interview to sharpen scope. Surfaces hidden assumptions, failure modes and non-negotiables before any code is written.
Elicitation Plan A Scope refinement
⚔️
q-deliberate
Step 2a · All plans
Multi-agent dialectical debate engine. Deploys 3 internal sub-roles: Proponent (builds the strongest case), Adversary (stress-tests risks and failure modes), Synthesizer (arbitrates and produces ADRs). Structures the problem as a DAG of decisions.
Architecture ADR generation Multi-agent All plans
🔀
q-delegate-context
Steps 4 & 5 · All plans
Keeps the orchestrator main thread clean by delegating heavy sub-tasks to isolated sub-contexts (FirstMate pattern). Selects executor, model, and effort automatically. Budgets: read ≤180s, web research ≤600s, implementation ≤900s. Hard cap: 2 correction rounds.
FirstMate pattern Codex CLI Antigravity CLI Context isolation
🧠
q-gbrain-assistant
Step 2b · All plans (optional)
Structured gateway to GBrain (Personal + Multi-Agent Knowledge Graph). Queries Engram (past decisions), GBrain (stack knowledge), and SkillVault in parallel. Surfaces historical patterns before committing to a new architecture.
Historical query Engram GBrain SkillVault
🔧
q-ci-fixer
Step 6 Sub-phase B · All plans
Surgical CI/CD repair. Operates only on git diff files, never the full codebase. 4-layer protocol: Format/Lint → Static Types → Logic Assertions → Coverage Gate. PROHIBITED: lowering coverage thresholds, blanket suppressors. Hard cap: 2 passes.
CI/CD Ruff · ESLint · Pyright Surgical SwarmForge
💾
q-session-wrap
Step 7c · All plans
Ordered session closure so the next session starts with full context. Persists to Engram (mem_session_summary), catalogs in SkillVault, and generates an atomic SQLite snapshot (VACUUM INTO). Always delivers a visible final report to the user.
Engram SkillVault SQLite snapshot Session closure
Architecture & Determinism

Advanced Protocols & Cold-Start Tools

Built for high-discipline software engineering. These protocols eliminate dirty working trees, context window saturation, and unverified AI hallucinations.

Workspace

Git Worktrees Isolation

The agent never switches branches or alters files in your active IDE workspace. Operates in isolated sibling directories ../{repo}-worktrees/{branch} and cleanly removes them post-merge.

Quality

Reproduction-First (SWE-agent)

Editing production code in src/ is strictly forbidden until an automated unit test in tests/ reproduces the bug in red. Verified in live terminal runs with automatic 3-strike rollback.

Tokens

Context Budgeting via AST

Prunes full function bodies in repositories with >10k LOC. Injects only AST signatures and interface contracts, reducing token footprint by up to 80% with zero architectural loss.

Workflow

Kiro-Style Task Gating

Dual-scope task definitions in P07_tasks.md: mandatory [CORE] tasks run automatically; optional enhancements [OPTIONAL:DISABLED] remain ignored until explicitly enabled by the human architect.

Tooling

q-checklist (Pre-Flight Matrix)

Zero-dependency interactive CLI (python tools/q-checklist/q_checklist.py) to select architecture, database, transport, testing, and worktree isolation in under 2 minutes.

Observability

Flight Recorder

Deterministic append-only event trail at .q-agent/flight_recorder.log tracking boundary checks, routing decisions, linter exit codes, and skill invocations.

Product

BMAD Squad Path in P04

Adopts the Product Manager role in P04_propose.md: formal User Personas, Agile User Stories (As a / I want / So that), and User Acceptance Criteria (UAC) before writing technical code.

🎓 Mentor / Copilot Mode

Want to drive the process manually? Prompt the agent: "Quiero ejecutar el flujo SDD manualmente paso a paso. No implementes nada por tu cuenta. Actúa únicamente como mi Mentor Arquitectónico: indícame en cada turno qué prompt o fase sigue, explícame el objetivo conceptual y entrégame la plantilla con las variables que debo completar.
